## Scope

Accenture decks ship across many contexts: client pitches, executive summaries, workshop kits, internal practitioner materials, partner co-branded engagements, sales support, conference talks. The brand canon below documents what is **shared across all of them**.

Anything specific to one practice, one industry vertical, one client engagement, or one methodology should be layered on top by the host project. This file does not invent that layer.

---

## What the brand stands for

The Accenture brand presents as **rigorous, evidence-led, action-oriented professional consulting**. Across any context, decks are expected to:

- Demonstrate command of the subject (specific numbers, named methods, cited sources)
- Respect the reader's time and seniority (no tutorial scaffolding, no marketing throat-clearing)
- Make recommendations actionable (named owners, named gates, measurable outcomes)
- Acknowledge uncertainty where it exists (warning callouts, ranges, named assumptions)

These are not voice rules (those live in [`VOICE.md`](./VOICE.md)); they are the **posture** the brand takes regardless of subject matter.

## Audience layers

A deck built from this template typically addresses one of four audience types. The host project specifies which; the canon below is the default starting point for each.

### A. Client executive / decision-maker

- **Who:** C-suite, board, business unit head, transformation lead at the client organisation
- **Priority:** business outcome, financial impact, risk position, decision criteria
- **Avoid:** technical deep-dives unless they own the technical question; methodology vocabulary without translation; hedging that reads as lack of conviction
- **Default mode mix:** light content with strong dark covers / dividers; one or two purple emphasis points

### B. Client technical / domain audience

- **Who:** architect, engineering lead, domain expert at the client organisation
- **Priority:** technical specifics, methodology, named approaches, evidence
- **Avoid:** marketing language; over-simplified diagrams; claims without citations
- **Default mode mix:** balanced light / dark; comfortable with denser content slides

### C. Internal Accenture practitioner

- **Who:** consultant, solution architect, sales lead, delivery manager preparing or reusing material
- **Priority:** reuse, named patterns, references back to the original source / methodology / vertical asset
- **Avoid:** content that requires the client context to make sense; "we" / "us" framing intended for clients
- **Default mode mix:** light, content-dense; less dark mode (internal decks are read at desks, not projected)

### D. Partner / mixed audience

- **Who:** mixed Accenture + partner stakeholders at a co-branded engagement
- **Priority:** clear roles, shared definitions, co-branded visual identity (per template slide 26)
- **Avoid:** language that positions Accenture over the partner; visual treatments that subordinate the partner brand
- **Default mode mix:** balanced; both logos respected on every slide that needs branding

When the host project picks the audience, the rest of the brand pack (voice, visual mode mix, content density) follows from this choice.

## Anti-audiences (brand-wide)

These audiences are **outside** the brand's default register. If the deck is genuinely aimed at one of them, the host project must adapt the voice and visual treatment accordingly — but this is the exception, not the rule.

- **Marketing-driven buyers** seeking aspirational narrative without proof. The default Accenture register reads as overly conservative to this audience.
- **Junior practitioners seeking tutorials.** The default register assumes the reader is senior and short on time; tutorial pacing requires a different voice.
- **Mass-market consumer audiences.** This template and the brand canon are built for B2B / enterprise contexts.

---

## What the brand promises (default Accenture posture)

A deck built from this template implicitly promises the reader:

1. **Specificity** — named methods, named tools, named numbers, named owners. No filler.
2. **Citations** — every load-bearing number traces back to a source the reader can verify.
3. **Acknowledged uncertainty** — ranges, scenarios, and `⚠` warnings where they apply. The brand does not pretend to know what it does not.
4. **Action** — what to do, when, with which gate or measurement. Strategy without action is not the brand's register.
5. **Visual discipline** — the deck looks Accenture (purple `#A100FF`, Graphik, light / dark / purple modes, clean grid). The reader recognises the source by the look.

---

## What the brand does not do

- **No vendor-marketing claims.** Numbers come from measurement or named sources, never from glossy collateral.
- **No "thought leadership" without proof.** If the deck makes a forecast, it carries scenarios and assumptions.
- **No anonymous "industry research".** Cite the research firm, the year, the methodology.
- **No decorative AI imagery** (glowing brains, abstract neural visualisations). Diagrams and data over decoration.
- **No closing on "Thank you" as the last meaningful slide.** Close on the CTA, the decision, or the insight; thank-you slides come after, as the screen left up during Q&A.

## Content pillars (host project layers on top)

The Accenture FY26 template carries no content pillars of its own — it is a visual and structural template. Content pillars (the topic territories a practice or engagement covers) are project-specific and live in the host project's own brand layer.

When this skill is invoked, the host project (or the user in conversation) provides the content. This file does not invent it.
